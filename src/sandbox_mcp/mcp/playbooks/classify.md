Определи категорию разработки (уровень риска T0–T4) для идеи или приложения пользователя. Уровень задаёт,
где приложение живёт, какие проверки проходит и сколько людей участвует. Границы проводятся по двум
признакам: где хранятся данные и какие это данные.

{idea_line}

Задай уточняющие вопросы, если ответов нет в описании или коде: какие данные хранятся и откуда берутся,
есть ли ПДн сотрудников или клиентов, коммерческая тайна, финансы; кто аудитория (команда, отдел, холдинг,
внешние пользователи); пишет ли приложение в корпоративные системы; есть ли загрузка файлов и вызовы ИИ.

Уровни:
- T0. Статичная страница в Claude: HTML-артефакт без хранения данных, без ПДн и КТ. Живёт в Claude,
  ссылка внутри организации, в реестре не регистрируется. Людей нет. Примеры: калькулятор стоимости
  отделки, чек-лист приёмки, прототип экрана.
- T1. Артефакт с БД Claude, без ПДн: служебная информация, доступ по группам. Остаётся в Claude, ПДн-скан
  при публикации, при находке автоповышение до T2. Примеры: трекер замечаний по объекту, опрос, доска идей.
- T2. Приложение с ПДн или КТ: ПДн сотрудников, коммерческая тайна, своя PostgreSQL в корпоративном
  закрытом контуре. Путь через BI Sandbox: матчинг с реестром, согласование, автосборка, автоконвейер
  проверок (SAST, секреты, зависимости, образ, DAST), инженер только после 3 неудачных циклов. Примеры:
  табель выхода людей по ФИО, справочник контактов, реестр смет и цен.
- T3. Данные из Data Lake: чтение сертифицированных корпоративных витрин через семантический слой, права по
  группам, в разработке только синтетика. Сценарий не проработан: до решения заявки идут по пути T4.
  Примеры: дашборд план-факт по объектам, отчёт по закупкам, сводка по дефектам.
- T4. Интеграции и критичное. 4а: запись в системы через одобренный канал, владелец системы согласует тип
  заявки, срок 1–2 недели. 4б: клиентские ПДн, финансы, аудитория «весь холдинг», внешний доступ: полный
  SSDLC, модель угроз, ИБ и DevOps, 2–6 недель. Путь через комитет и команды IT. Примеры: 4а заявка на
  закупку в 1С; 4б портал подрядчика, расчёт премий, клиентский кабинет.

Модификаторы, которые автоматически повышают уровень:
- загрузка файлов и документов: минимум T2;
- ИИ внутри приложения: на T0–T1 только встроенный Claude, с T2 вызовы через корпоративный шлюз с лимитом
  токенов на приложение;
- запись в корпоративные системы: T4а;
- внешние пользователи, клиентские ПДн, финансы или аудитория «весь холдинг»: T4б.

Открытые вопросы модели (сообщи пользователю, если они влияют на решение): границу коммерческой тайны
(T2 или сразу T4 для «строго конфиденциального») должна подтвердить ИБ; T3 до решения идёт как T4.

Результат оформи так:
1. Уровень: T0 / T1 / T2 / T3 / T4а / T4б и сработавшие модификаторы.
2. Почему: какие данные, аудитория, интеграции привели к уровню.
3. Что дальше: T0–T1 остаются в Claude (артефакт, без регистрации); T2 идёт в BI Sandbox (в пилоте:
   публичный GitHub → assess_application → validate_and_deploy в TEST, промпт publish); T3 и T4 через
   комитет и команды IT, песочница TEST для них не используется.
4. Срок до прода по модели: T0 сразу, T1 минуты, T2 до 1 дня, T3 1–3 дня, T4а 1–2 недели, T4б 2–6 недель.
   Это оценка целевой модели до пилота, не обязательство.

Если данных для решения не хватает, не присваивай уровень по умолчанию: задай вопросы. При сомнении между
двумя уровнями выбирай более высокий и объясни это.
