# Пакет для загрузки в BI Sandbox (ZIP)

Цель: один архив, который платформа примет без вопросов: код, который собирается, и PRD, по которому
понятно, что это и зачем. Делай шаги по порядку и показывай пользователю, что получилось.

## 1. PRD.md в корне проекта

Если PRD ещё нет, составь его вместе с пользователем (скилл sandbox-classify даёт уровень):

```
# <Название приложения>
Автор: <ФИО, подразделение, контакт>      Дата: <YYYY-MM-DD>
Уровень: <T0 | T1 | T2 | T3 | T4а | T4б>   Модификаторы: <или «нет»>

## Проблема и ценность
<1–3 абзаца: что болит, для кого, эффект в часах или деньгах в месяц>

## Аудитория и охват
<кто пользуется: команда / отдел / холдинг; сколько человек; доступ по группам>

## Данные
<какие данные хранит и откуда берёт; ПДн / КТ / финансы: да или нет; срок хранения>

## Интеграции
<читает / пишет ли в корпоративные системы; загрузка файлов; вызовы ИИ>

## Как проверить
<3–5 сценариев приёмки: что открыть, что нажать, что должно получиться>

## Владелец и поддержка
<кто владелец после запуска, канал для инцидентов, желаемый срок жизни>
```

## 2. Код, который собирается

- Тип проекта должен быть одним из принимаемых: статика (`index.html` в корне или в `dist/build/public/out`),
  node_build (`package.json` со скриптом `build`), Dockerfile. Иначе платформа отклонит пакет.
- Прогони сборку локально (`npm run build` или `docker build .`) и убедись, что она проходит.
- Для статики не клади собранный мусор поверх исходников: либо исходники со скриптом build, либо готовая
  папка `dist`, не обе.

## 3. Чистка перед упаковкой

Удали или исключи: `.env*`, ключи и токены в коде (замени на переменные окружения и опиши их в README),
`node_modules`, `.git`, кэши сборки, дампы баз, тестовые данные с реальными ФИО. Прогони быстрый поиск:

```bash
grep -rniE "api[_-]?key|secret|password|token|BEGIN (RSA|OPENSSH) PRIVATE KEY" --exclude-dir=node_modules --exclude-dir=.git .
```

Каждую находку либо убери, либо объясни пользователю, почему это не секрет. Платформа повторит проверку
Gitleaks и остановит выпуск при любой находке.

## 4. ZIP

Имя: `<slug>-<YYYYMMDD>.zip`, внутри одна папка с проектом, PRD.md в её корне.

```bash
zip -r <slug>-<YYYYMMDD>.zip <папка> -x "*/node_modules/*" "*/.git/*" "*/.env*" "*/dist/*cache*" "*.DS_Store"
unzip -l <slug>-<YYYYMMDD>.zip | tail -3
```

Размер должен быть разумным (до 50 МБ); если больше, в архив попало лишнее.

## 5. Куда загрузить

- Пилот Sandbox MCP (текущий путь): платформа принимает код из публичного GitHub, а не ZIP. Если у
  пользователя есть GitHub, лучше сразу скилл sandbox-publish: push → assess_application →
  validate_and_deploy → status. ZIP в этом случае остаётся как архив для реестра и приёмки.
- MVP «AI Sandbox» (стрим 1, загрузка ZIP → контейнер → ссылка за SSO): загрузить ZIP через веб-форму
  стенда после корпоративного входа. Адрес стенда даёт администратор песочницы, принимаются типы static и
  node_build, Dockerfile автора игнорируется.
- T3 и T4: ZIP с PRD уходит не на платформу, а в заявку комитету и команде IT; объясни маршрут.

В конце покажи пользователю: путь к ZIP, его размер, список верхнего уровня, уровень T0–T4 и выбранный
маршрут загрузки.
